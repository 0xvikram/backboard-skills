# Scaffold-ETH 2 recipes

All code was checked against a `create-eth@2.0.23` Hardhat project on 2026-10-19 (frontend: viem 2.53.1, wagmi 2.19.5, Next 16.2.12). "Tested" means it type-checked and built, and where noted it also ran.

---

## 1. Create the project (Hardhat or Foundry)

**Goal:** a new monorepo with no prompts.

```bash
npx create-eth@2.0.23 my-dapp -s hardhat
# or
npx create-eth@2.0.23 my-dapp -s foundry
```

**Which flavour?**

| | Hardhat (`-s hardhat`) | Foundry (`-s foundry`) |
|---|---|---|
| Stack in 2.0.23 | Hardhat 3, hardhat-deploy 2 (rocketh), TypeScript deploy scripts in `deploy/` | Forge scripts in `script/`, Anvil local node |
| Tests | Mocha + ethers (`yarn hardhat:test`) | Solidity tests (`yarn foundry:test`), fast fuzzing |
| Extra install | none | Foundry >= 1.4.0 must be installed first |
| Deployer key | encrypted in `packages/hardhat/.env` | Foundry keystore in `~/.foundry/keystores/` |

Pick Foundry if your team writes Solidity tests. Pick Hardhat if you want everything in TypeScript and no extra install. The frontend is the same for both. The official agent skill defaults to Foundry.

**Notes:** you cannot switch flavour later, so make a new project. Extensions are added with `-e` at this step only (recipe 7).

Source: https://docs.scaffoldeth.io/quick-start/installation, `npx create-eth --help`.

## 2. Local chain, deploy, and the Debug Contracts page

**Goal:** edit a contract and see it in a UI in under a minute.

```bash
yarn chain                      # terminal 1
yarn deploy                     # terminal 2 (run again after every contract change)
yarn start                      # terminal 3 → http://localhost:3000/debug
```

- Contracts: `packages/hardhat/contracts/` (Foundry: `packages/foundry/contracts/`).
- Deploy scripts: `packages/hardhat/deploy/` (Foundry: `packages/foundry/script/Deploy.s.sol`, which calls `DeployYourContract.s.sol`).
- Deploy one script only: Hardhat `yarn deploy --tags YourContract` (the tag is set in the script's options); Foundry `yarn deploy --file DeployMyContract.s.sol`.
- Every deploy rewrites `packages/nextjs/contracts/deployedContracts.ts`. The Debug page and the hooks read from that file.
- Hardhat 2.0.23 deploy script shape (generated by the template):

```ts
import { deployScript, artifacts } from "../rocketh/deploy.js";

export default deployScript(
  async env => {
    const { deployer } = env.namedAccounts;
    await env.deploy("YourContract", {
      account: deployer,
      artifact: artifacts.YourContract,
      args: [deployer],
    });
  },
  { tags: ["YourContract"] },
);
```

**Notes:** hardhat-deploy reuses an existing deployment when the bytecode and arguments have not changed (tested: a second `yarn deploy` reused the address). `yarn fork` starts a mainnet fork instead of a clean chain.

Source: https://docs.scaffoldeth.io/quick-start/environment, https://docs.scaffoldeth.io/deploying/deploy-smart-contracts

## 3. Scaffold hooks: read, write, event history

**Goal:** typed contract calls by contract name, with no ABI or address plumbing.

```tsx
"use client";

import { useState } from "react";
import type { NextPage } from "next";
import { parseEther } from "viem";
import { useScaffoldEventHistory, useScaffoldReadContract, useScaffoldWriteContract } from "~~/hooks/scaffold-eth";

const Page: NextPage = () => {
  const [newGreeting, setNewGreeting] = useState("");

  const { data: greeting } = useScaffoldReadContract({
    contractName: "YourContract",
    functionName: "greeting",
  });

  const { writeContractAsync: writeYourContractAsync, isMining } = useScaffoldWriteContract({
    contractName: "YourContract",
  });

  const { data: events, isLoading } = useScaffoldEventHistory({
    contractName: "YourContract",
    eventName: "GreetingChange",
    watch: true,
  });

  return (
    <div className="flex flex-col items-center gap-4 pt-10">
      <p>Greeting: {greeting}</p>
      <input className="input input-bordered" value={newGreeting} onChange={e => setNewGreeting(e.target.value)} />
      <button
        className="btn btn-primary"
        disabled={isMining}
        onClick={async () => {
          try {
            await writeYourContractAsync({
              functionName: "setGreeting",
              args: [newGreeting],
              value: parseEther("0.01"), // only for payable functions
            });
          } catch (e) {
            console.error("Error setting greeting:", e);
          }
        }}
      >
        {isMining ? "Mining..." : "Set greeting"}
      </button>
      <ul>
        {isLoading && <li>Loading events...</li>}
        {events?.map(e => (
          <li key={`${e.transactionHash}-${e.logIndex}`}>
            {e.args.greetingSetter}: {e.args.newGreeting}
          </li>
        ))}
      </ul>
    </div>
  );
};

export default Page;
```

**Notes:**
- Tested in a headless browser against `yarn chain`: the greeting and the `GreetingChange` list rendered with live data.
- `contractName`, `functionName`, `args` and `e.args.*` are typed from `deployedContracts.ts` + `externalContracts.ts` **for `targetNetworks[0]` only**. A contract that exists only on another chain gives `Type '"X"' is not assignable to type '"YourContract"'`. See recipe 6 and errors.md.
- `useScaffoldReadContract` watches new blocks by default (`watch: true`).
- `useScaffoldEventHistory` options: `fromBlock` (defaults to `deployedOnBlock` from the contracts file, else 0), `toBlock`, `filters` (indexed params only), `blockData`, `transactionData`, `receiptData`, `blocksBatchSize` (default 500; lower it on RPCs with log-range caps), `enabled`, `chainId`.
- All three hooks take an optional `chainId` to pick another configured network.
- Also available: `useScaffoldWatchContractEvent`, `useScaffoldContract`, `useDeployedContractInfo`, `useTransactor`.

Source: https://docs.scaffoldeth.io/hooks/useScaffoldReadContract, https://docs.scaffoldeth.io/hooks/useScaffoldWriteContract, https://docs.scaffoldeth.io/hooks/useScaffoldEventHistory

## 4. Add a sponsor chain as a target network

**Goal:** the frontend talks to World Chain / Unichain / Arc / Hedera / 0G / Whitechain, and Hardhat or Foundry can deploy there. The frontend and the contracts package keep **separate** network lists, so update both.

### 4a. Frontend: `packages/nextjs/scaffold.config.ts`

Change only the marked parts of the generated file (tested; type-check, build and live reads passed):

```ts
import * as chains from "viem/chains";
// import { arcMainnet } from "./utils/customChains"; // uncomment if you add Arc mainnet (4b)

// ...BaseConfig type and DEFAULT_ALCHEMY_API_KEY stay as generated...

const scaffoldConfig = {
  targetNetworks: [
    chains.worldchainSepolia, // 4801  ← first = default network and the one hook types follow
    // chains.unichainSepolia, // 1301
    // chains.arcTestnet,      // 5042002
    // chains.hederaTestnet,   // 296
    // chains.zeroGTestnet,    // 16602 (0G Galileo)
    // chains.whitechainSepolia, // 1874
    // arcMainnet,             // 5042
  ],
  pollingInterval: 3000,
  alchemyApiKey: process.env.NEXT_PUBLIC_ALCHEMY_API_KEY || DEFAULT_ALCHEMY_API_KEY,
  rpcOverrides: {
    // viem 2.53.1 (pinned by the template) still has Arc testnet's old RPC, which no longer answers
    [chains.arcTestnet.id]: "https://rpc.testnet.arc.io",
  },
  walletConnectProjectId: process.env.NEXT_PUBLIC_WALLET_CONNECT_PROJECT_ID || "3a8170812b534d0ff9d794f19a901d64",
  burnerWalletMode: "localNetworksOnly",
} as const satisfies ScaffoldConfig;
```

While you still develop locally, keep `chains.hardhat` first and add the sponsor chain after it. Note that the burner wallet disappears as soon as a non-local chain is in the list (`localNetworksOnly`). Set `burnerWalletMode: "allNetworks"` if you want it on testnets too; you must fund it yourself.

### 4b. A chain viem lacks (or lacks an RPC for): `defineChain`

viem 2.53.1 ships `arc` (5042) **with no RPC URL**, so you need your own definition. `packages/nextjs/utils/customChains.ts` (tested, live read returned chain id 5042):

```ts
import { defineChain } from "viem";

export const arcMainnet = defineChain({
  id: 5042,
  name: "Arc",
  nativeCurrency: { name: "USDC", symbol: "USDC", decimals: 18 },
  rpcUrls: { default: { http: ["https://rpc.mainnet.arc.io"] } },
  blockExplorers: { default: { name: "Arc Explorer", url: "https://explorer.arc.io" } },
});
```

Use the same pattern for any chain missing from `viem/chains`. RPC and explorer values: https://docs.arc.io/arc/references/rpc-endpoints.md.

### 4c. Hardhat: `packages/hardhat/hardhat.config.ts`

Add entries inside `networks`. Hardhat 3 **requires** `type: "http"`, which the docs snippet leaves out:

```ts
    worldchainSepolia: { type: "http", url: "https://worldchain-sepolia.g.alchemy.com/public", accounts: [deployerPrivateKey] },
    unichainSepolia: { type: "http", url: "https://sepolia.unichain.org", accounts: [deployerPrivateKey] },
    arcTestnet: { type: "http", url: "https://rpc.testnet.arc.io", accounts: [deployerPrivateKey] },
    hederaTestnet: { type: "http", url: "https://testnet.hashio.io/api", accounts: [deployerPrivateKey] },
    zeroGTestnet: { type: "http", url: "https://evmrpc-testnet.0g.ai", accounts: [deployerPrivateKey] },
    whitechainSepolia: { type: "http", url: "https://rpc.testnet.whitechain.io", accounts: [deployerPrivateKey] },
```

Tested: a `hardhat run` script that connects to each of these returned the right chain ID and block number, and `yarn account` listed a balance on each.

### 4d. Foundry: `packages/foundry/foundry.toml`

```toml
[rpc_endpoints]
# ...existing entries...
worldchainSepolia = "https://worldchain-sepolia.g.alchemy.com/public"
unichainSepolia = "https://sepolia.unichain.org"
arcTestnet = "https://rpc.testnet.arc.io"
hederaTestnet = "https://testnet.hashio.io/api"
zeroGTestnet = "https://evmrpc-testnet.0g.ai"
whitechainSepolia = "https://rpc.testnet.whitechain.io"
```

`yarn deploy --network <name>` only accepts names that exist in `[rpc_endpoints]`. (Not run: Foundry was not installed on the test machine.)

Source: https://docs.scaffoldeth.io/recipes/add-custom-chain, https://docs.scaffoldeth.io/deploying/deploy-nextjs-app (targetNetworks), https://docs.scaffoldeth.io/deploying/deploy-smart-contracts. Chain IDs and RPCs: [chains.md](chains.md).

## 5. Deploy to a testnet and verify

**Goal:** your contract on a sponsor testnet, verified, with the frontend pointing at it.

**Hardhat flavour** (steps 1 to 3 tested; the deploy was tried with an unfunded throwaway key and failed as expected):

```bash
yarn generate                    # new random deployer; asks for a password; writes DEPLOYER_PRIVATE_KEY_ENCRYPTED to packages/hardhat/.env
# or: yarn account:import        # paste an existing testnet-only key; stored encrypted
yarn account                     # asks for the password; prints the address and balance on every network in hardhat.config.ts
# fund the address from the chain's faucet, then:
yarn deploy --network worldchainSepolia      # asks for the password
yarn verify --network worldchainSepolia sourcify
```

**Foundry flavour** (from the docs, not run here):

```bash
yarn generate                    # creates a Foundry keystore (asks for a name and password)
yarn account:import              # or import a key into ~/.foundry/keystores
yarn deploy --network worldchainSepolia --keystore <KEYSTORE_NAME>
yarn verify --network worldchainSepolia
```

**Verification:**
- Hardhat `yarn verify` wraps `rocketh-verify`. Subcommands: `etherscan` (default; Etherscan V2 API with `ETHERSCAN_API_KEY`), `sourcify`, `blockscout --endpoint <url>`. Run `yarn verify --help`.
- **Sourcify** lists every sponsor testnet (4801, 1301, 5042002, 296, 16602, 1874) and needs no key. Checked at https://sourcify.dev/server/chains on 2026-10-19.
- **Etherscan V2** lists World Chain (480, 4801), Unichain (130, 1301) and Arc mainnet (5042). Checked at https://api.etherscan.io/v2/chainlist.
- Foundry's `VerifyAll.s.sol` calls `forge verify-contract --chain <id>` with your `foundry.toml` `[etherscan]` settings. For Sourcify-only chains run `forge verify-contract <ADDRESS> <ContractName> --chain <ID> --verifier sourcify` yourself ([forge docs](https://getfoundry.sh/forge/reference/forge-verify-contract)).

**Then:** commit the regenerated `packages/nextjs/contracts/deployedContracts.ts`. It is not gitignored, and Vercel needs it. Put that chain first in `targetNetworks`.

**Notes:** never use a key that holds real funds. `yarn account:reveal-pk` prints the decrypted key, so only run it on your own machine. An unfunded deployer fails with `ProviderError: gas required exceeds allowance (0)`.

Source: https://docs.scaffoldeth.io/deploying/deploy-smart-contracts

## 6. External contracts on a sponsor chain

**Goal:** call a contract you did not deploy (a sponsor's token, router, registry) with the same typed hooks.

`packages/nextjs/contracts/externalContracts.ts` (tested with the WETH predeploy on World Chain Sepolia; the page rendered the live `symbol` and `totalSupply`):

```ts
import { erc20Abi } from "viem";
import { GenericContractsDeclaration } from "~~/utils/scaffold-eth/contract";

const externalContracts = {
  4801: {
    // deployedOnBlock: block where event scans start (also avoids a type error, see errors.md)
    WETH: { address: "0x4200000000000000000000000000000000000006", abi: erc20Abi, deployedOnBlock: 35900000 },
  },
} as const;

export default externalContracts satisfies GenericContractsDeclaration;
```

With `chains.worldchainSepolia` first in `targetNetworks`:

```tsx
const { data: supply } = useScaffoldReadContract({ contractName: "WETH", functionName: "totalSupply" });
const { data: transfers } = useScaffoldEventHistory({
  contractName: "WETH",
  eventName: "Transfer",
  fromBlock: 35937000n,
  blocksBatchSize: 100, // the public World Chain RPC caps eth_getLogs at 100 blocks
});
```

To read a contract on a chain that is **not** `targetNetworks[0]`, the scaffold hook types do not see it. Use wagmi directly (tested):

```tsx
import { erc20Abi } from "viem";
import { useReadContract } from "wagmi";

const { data: wethSupply } = useReadContract({
  address: "0x4200000000000000000000000000000000000006",
  abi: erc20Abi,
  functionName: "totalSupply",
  chainId: 4801, // must be in targetNetworks
});
```

Source: https://docs.scaffoldeth.io/external-contracts

## 7. Extensions (create-eth -e)

**Goal:** start with a feature already wired in. You can add only **one** extension, and only when you create the project.

```bash
npx create-eth@2.0.23 my-dapp -s hardhat -e erc-20      # tested: adds SE2Token.sol and an /erc20 page
npx create-eth@latest -e {github-user}/{repo}:{branch}  # third-party extension (create-eth warns that it is untrusted)
```

Curated extensions that fit a hackathon (list in create-eth `src/extensions/create-eth-extensions.ts`):

| `-e` value | What you get |
|---|---|
| `erc-20` | ERC-20 token contract plus balance and transfer UI |
| `erc-721` | NFT contract with mint, list and transfer UI |
| `eip-712` | Typed-data signing, sending and verifying |
| `eip-5792` | Batched wallet calls |
| `ponder` | ponder.sh indexer set up for your contracts |
| `subgraph` | The Graph subgraph set up |
| `envio` | Envio indexer |
| `x402` | Pay-per-request API routes and pages with x402 |
| `drizzle-neon` | Postgres via Drizzle + Neon |
| `randao` | On-chain randomness from RANDAO |
| `porto` | porto.sh SDK |
| `signinwithethereum/scaffold-siwe-ext` | Sign-In with Ethereum |
| `metamask/gator-extension` | MetaMask Smart Accounts and ERC-7710 delegations |

Already started without one? Use the matching skill in `.agents/skills/` (erc-721, siwe, ponder, subgraph, x402, eip-5792, drizzle-neon, openzeppelin) and ask your agent to apply it.

Source: https://docs.scaffoldeth.io/extensions/howToInstall, https://scaffoldeth.io/extensions, https://github.com/scaffold-eth/create-eth/blob/main/src/extensions/create-eth-extensions.ts, https://docs.scaffoldeth.io/build-with-ai/skills

## 8. Deploy the frontend to Vercel

**Goal:** a public URL for judges.

From the CLI (repo root):

```bash
yarn vercel:login
yarn vercel            # preview URL
yarn vercel --prod     # production URL
yarn vercel:yolo --prod   # skip type and lint checks (last resort)
```

From GitHub (the docs recommend this): import the repo in Vercel and set **Root Directory** to `packages/nextjs`, where `vercel.json` (`"installCommand": "yarn install"`) and the app live ([Vercel monorepos](https://vercel.com/docs/monorepos)). Add `NEXT_PUBLIC_ALCHEMY_API_KEY` and `NEXT_PUBLIC_WALLET_CONNECT_PROJECT_ID` as environment variables. To skip type errors in a Git-connected build, set `NEXT_PUBLIC_IGNORE_BUILD_ERROR=true`.

Checklist before deploying:
1. `targetNetworks[0]` is your live testnet, not `hardhat`.
2. `deployedContracts.ts` for that chain is committed.
3. `yarn next:build` passes locally (it runs eslint, then `next build`).

Alternative: `yarn ipfs` builds a static export and uploads it to BuidlGuidl IPFS.

Not tested: no Vercel deploy was run (it needs a login and uploads code). The local `yarn next:build` that Vercel runs passed.

Source: https://docs.scaffoldeth.io/deploying/deploy-nextjs-app, https://docs.scaffoldeth.io/disable-type-linting-error-checks
