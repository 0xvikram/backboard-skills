# Scaffold-ETH 2 quickstart (full)

Based on https://docs.scaffoldeth.io/quick-start/installation and https://docs.scaffoldeth.io/quick-start/environment, checked against a project generated with `create-eth@2.0.23` on 2026-10-19.

## 1. Requirements

- **Node >= 22.10.** The generated root `package.json` has `"engines": { "node": ">=22.10.0" }`. The docs page still says 20.18.3, so trust the generated file.
- **Yarn**, any version. `create-eth` stops with "Yarn is not installed" if `yarn` is not on your PATH. The project pins Yarn 4.13.0 through `.yarnrc.yml` (`yarnPath`), so a global Yarn 1 works too. To get Yarn: `corepack enable` or `npm i -g yarn`.
- **Git.**
- **Foundry flavour only:** Foundry >= 1.4.0 (`forge --version`). create-eth checks this before it does anything, even with `--skip-install`. Install instructions: https://getfoundry.sh/introduction/installation

No accounts or API keys are needed for local work. The template ships shared Alchemy, Etherscan and WalletConnect keys for prototyping. They are rate-limited, so get your own before demo day (see step 5).

## 2. Create the project

Interactive:

```bash
npx create-eth@latest
```

Non-interactive (tested; this is also what the official agent skill at https://docs.scaffoldeth.io/SKILL.md runs):

```bash
npx create-eth@2.0.23 my-dapp -s hardhat      # Hardhat 3 + hardhat-deploy 2
npx create-eth@2.0.23 my-dapp -s foundry      # Forge scripts + Anvil
npx create-eth@2.0.23 . -s foundry            # scaffold into the current empty folder
```

Flags (from `npx create-eth@2.0.23 --help`): `-s/--solidity-framework`, `-e/--extension <name>` (one extension, only at creation time), `--skip`/`--skip-install`.

The first install takes several minutes. It also runs `git init` and makes a first commit.

## 3. Layout

```
my-dapp/
  AGENTS.md, CLAUDE.md          # agent instructions (read these)
  .agents/skills/               # official feature skills (erc-721, siwe, ponder, x402, ...)
  packages/hardhat/             # or packages/foundry/
    contracts/YourContract.sol
    deploy/00_deploy_your_contract.ts   (Foundry: script/Deploy.s.sol, script/DeployYourContract.s.sol)
    hardhat.config.ts                    (Foundry: foundry.toml)
    .env                                 # DEPLOYER_PRIVATE_KEY_ENCRYPTED, ALCHEMY_API_KEY, ETHERSCAN_API_KEY
  packages/nextjs/
    scaffold.config.ts          # targetNetworks, rpcOverrides, burnerWalletMode, keys
    contracts/deployedContracts.ts   # generated by yarn deploy; do not edit
    contracts/externalContracts.ts   # contracts you did not deploy
    hooks/scaffold-eth/         # useScaffoldReadContract, useScaffoldWriteContract, ...
    app/debug/                  # Debug Contracts page
```

## 4. Run locally (three terminals)

```bash
yarn chain     # local node on http://127.0.0.1:8545, chain id 31337
yarn deploy    # compile, deploy YourContract, regenerate deployedContracts.ts
yarn start     # Next.js on http://localhost:3000
```

Tested output of `yarn deploy` (Hardhat flavour):

```
- Deploying YourContract  with tx: ...
    => 0x5fbdb2315678afecb367f032d93f642f64180aa3
👋 Initial greeting: Building Unstoppable Apps!!!
📝 Updated TypeScript contract definition file on ../nextjs/contracts/deployedContracts.ts
```

Open http://localhost:3000/debug. Every public function of every deployed contract gets a form. A burner wallet connects on its own (or pick **Connect Wallet → Burner Wallet**); then use the faucet button in the header to fund it with local ETH. The burner wallet only shows while every network in `targetNetworks` is the local `hardhat` chain (see `burnerWalletMode` in `scaffold.config.ts`).

## 5. Environment variables (placeholders only)

`packages/nextjs/.env.local`:

```
NEXT_PUBLIC_ALCHEMY_API_KEY=<YOUR_ALCHEMY_KEY>
NEXT_PUBLIC_WALLET_CONNECT_PROJECT_ID=<YOUR_WALLETCONNECT_PROJECT_ID>
```

`packages/hardhat/.env` (Foundry: `packages/foundry/.env`):

```
ALCHEMY_API_KEY=<YOUR_ALCHEMY_KEY>
ETHERSCAN_API_KEY=<YOUR_ETHERSCAN_KEY>
# Do not type this by hand. Run `yarn generate` or `yarn account:import`.
DEPLOYER_PRIVATE_KEY_ENCRYPTED=
```

Where to get keys:
- Alchemy: https://dashboard.alchemy.com/ → **Apps → Create new app** → copy the API key.
- WalletConnect / Reown project ID: https://cloud.walletconnect.com → create a project → copy the Project ID.
- Etherscan (one key works for all Etherscan V2 chains): https://etherscan.io/myapikey.

Source: https://docs.scaffoldeth.io/deploying/deploy-smart-contracts (section "Configuration of Third-Party Services").

## 6. Complete runnable example

`packages/nextjs/app/greet/page.tsx` (tested: type-checks, builds, and in a headless browser the burner wallet sent `setGreeting` and the page showed the new value):

```tsx
"use client";
import type { NextPage } from "next";
import { useScaffoldReadContract, useScaffoldWriteContract } from "~~/hooks/scaffold-eth";

const Greet: NextPage = () => {
  const { data: greeting } = useScaffoldReadContract({ contractName: "YourContract", functionName: "greeting" });
  const { writeContractAsync, isMining } = useScaffoldWriteContract({ contractName: "YourContract" });
  return (
    <div className="flex flex-col items-center gap-4 pt-10">
      <p>Greeting: {greeting}</p>
      <button
        className="btn btn-primary"
        disabled={isMining}
        onClick={() => writeContractAsync({ functionName: "setGreeting", args: ["gm Mumbai"] }).catch(console.error)}
      >
        Set greeting
      </button>
    </div>
  );
};
export default Greet;
```

Run `yarn start` and open http://localhost:3000/greet.

## 7. Before you push

```bash
yarn next:check-types   # tsc for the frontend
yarn next:build         # eslint + next build (what Vercel runs)
yarn hardhat:test       # or: yarn foundry:test
```

Note: `yarn hardhat:check-types` fails on a fresh create-eth@2.0.23 project because of rocketh type errors in `rocketh/*.ts`. Deploys still work. See errors.md.
